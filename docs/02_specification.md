# AI curator — 仕様定義

`docs/01_requirements.md` の要件を、パイプライン各段の入出力と振る舞いに落とす。

根拠の出典表記: `(BS L*)` は `docs/ai_curator_brainstorm.md` の行番号、URL は公式ドキュメントを指す。
数値パラメータ（重み・閾値・頻度の具体値）は未確定であり、`【暫定】` と明記した値は PoC・実運用で調整する (BS L114)。

## 1. パイプライン全体

```
[Sources] → Fetch/Ingest → Normalize → Dedup/Score → Store → Digest生成 → Deliver
```

6 段パイプライン。安い処理を先に置き、LLM に渡る件数を段階的に絞る (BS L11-18)。

実行系統は 2 つに分離する (BS L106):

| 系統 | 頻度 | 処理 |
|---|---|---|
| Fetch 系 | 高頻度【暫定: 1〜3 時間ごと】 | Fetch → Normalize → 機械的 Dedup → Store |
| Digest 系 | 1 日 1 回 | Embedding → 意味的 Dedup → Score → Digest 生成 → Deliver |

## 2. ソース仕様 (BS L55-63)

| ソース | 取得方式 | エンドポイント | 本文抽出 |
|---|---|---|---|
| GitHub Releases | REST API | `GET /repos/{owner}/{repo}/releases`（https://docs.github.com/en/rest/releases/releases） | 不要（release note が本文） |
| Hacker News | Algolia API | `https://hn.algolia.com/api/v1/search_by_date`（https://hn.algolia.com/api） | リンク先はタイトル+メタのみ利用【暫定】 |
| Medium | RSS feed（著者/タグ） | `https://medium.com/feed/@{author}` 等 | テンプレ抽出 = 著者 feed の `content:encoded`（本文全文を含む。記事ページ直接 fetch はボットチャレンジでブロック — 実測 2026-07-06）(BS L59) |
| martinfowler.com | Atom feed | `https://martinfowler.com/feed.atom`（実在確認済み、BS L63） | 個別対応 = 記事ページの `<main>` 要素から抽出（実測 2026-07-06）(BS L60) |

- 監視対象（リポジトリ・著者・タグの具体リスト）はユーザー設定とし、コードから分離する
- 本文抽出は「テンプレ化」「個別対応」の 2 方式を実装し、ソースごとにどちらかを割り当てる (BS L62)

## 3. 正規化スキーマ

全ソースの出力を以下の共通形式に揃える。保存可否は法務方針 (BS L74-77) に従う。

| フィールド | 内容 | 永続化 |
|---|---|---|
| `url` | 正規化済み URL（トラッキングパラメータ除去） | ○ |
| `title` | タイトル | ○ |
| `source` | 媒体名・ソース種別 | ○ |
| `published_at` | 公開日時 | ○ |
| `feed_summary` | フィード提供の要約（あれば） | ○ |
| `body` | 抽出本文 | ×（処理中のみメモリ、破棄）(BS L76) |
| `content_hash` | 本文のハッシュ（SimHash 用） | ○ |

冪等キーは正規化 URL or コンテンツハッシュの unique 制約【暫定: 正規化 URL】。確定は PoC 後 (BS L113)。

## 4. Dedup 仕様

2 段階で実施する (BS L23-25)。

1. **機械的 Dedup**（Fetch 系・保存前）
   - SimHash/MinHash により完全重複・ほぼ重複を除去
   - LLM・Embedding を使わない（コスト 0 に近い）
2. **意味的 Dedup**（Digest 系・Embedding 後）
   - cosine 類似が閾値【暫定: 0.9】以上の記事をクラスタ化
   - クラスタごとに代表 1 本を選出【暫定: ソース信頼度が高く公開日時が新しいもの】

## 5. Embedding 仕様

- Workers AI の bge 系モデルを使用（トークン課金・原文非保持）(BS L24)
- モデル候補は**多言語モデルに限定**する（確定 2026-07-06 ユーザー判断）。理由: 日本語ソース導入を見込むため、英語特化モデルの採用は将来のベクトル空間分裂（異モデル間で cosine 比較不能）か全件再 Embedding を強制する
  - `@cf/baai/bge-m3`: 多言語・context window 60,000 トークン・最安（$0.012/M input tokens）。第一候補【暫定】
  - `@cf/qwen/qwen3-embedding-0.6b`: 多言語（提供元 Qwen の説明。Cloudflare ページに明記なし、検証③で日本語動作を確認）・context window 8,192 トークン・同額（$0.012/M input tokens）。代替候補
  - 各モデルページ: https://developers.cloudflare.com/workers-ai/models/
- Embedding 入力: タイトル + 要約（or 本文冒頭）【暫定】。何を Embedding するかは PoC 検証項目 (BS L31)
- ベクトルは原文復元不可のため永続化できる (BS L77)

## 6. スコアリング仕様

### 6.1 スコア式 (BS L26)

```
score = 関心類似 × w1 + 鮮度 × w2 + ソース信頼度 × w3
```

- 重み w1〜w3 は未確定。PoC は「上位が読む価値ある順に見えるか」の目視確認まで (BS L91-95)

### 6.2 関心類似 — 複数ベクトル方式（確定）(BS L42-47)

- 関心プロファイルは関心軸ごとに独立したベクトルを持つ。軸は 4 つで確定（2026-07-06 ユーザー回答）: Web FW / AI / Agentic Coding / Software Designing
- `関心類似 = max(記事ベクトルと各関心軸ベクトルの cosine)`（OR 的判定）
- 最大値を与えた軸を「ヒット軸」として記録し、digest の選定理由に使う (BS L47)

### 6.3 鮮度・ソース信頼度

- 鮮度: 公開日時からの経過時間による減衰【暫定: 指数減衰】
- ソース信頼度: ソースごとの固定値【暫定】。種別ごとの重み分岐は実運用フェーズ (BS L100)

## 7. 関心プロファイル仕様 (BS L36-40)

| 系統 | 内容 | フェーズ |
|---|---|---|
| 明示指定（シード） | 興味トピック/代表記事のテキストをベクトル化し関心軸を初期構築 | PoC から |
| 暗黙学習（フィードバック） | 既読/評価を関心軸ベクトルへ還流して更新 | 実運用 |
| 明示ルール（フィルタ） | ドメイン単位の常時含む/除外 | 実運用 |

フィルターバブル対策の混合比率は未確定 (BS L114)。

## 8. Digest 仕様

- 生成頻度: 1 日 1 回 (BS L106)
- digest は「当日傾向サマリ（§8.1）」＋「厳選記事リスト（§8.2）」の 2 部構成とする

### 8.1 当日傾向サマリ（FR-6.1）

- 対象は選抜前の当日母集団（機械的 Dedup 後の全記事）。選抜された少数だけでは見えない全体傾向を俯瞰する
- 提示内容（暫定）:
  - 関心軸ごとのヒット件数分布（各記事のヒット軸 = `max(cosine)` を与えた軸で集計）
  - 意味的 Dedup のクラスタから見た当日の主要トピック（大きいクラスタ = 話題が集中した領域）
  - ソース別の件数
  - 上記を入力に LLM が 2〜3 文の日本語で当日の傾向を叙述【暫定】
- 集計値・要約のみを扱い、個別記事の原文を含まない（§10 に抵触しない）
- 傾向サマリは当日限りの自前生成物。保存可否は §10 に従う（保存する場合は digest 本文の一部として）

### 8.2 厳選記事リスト

- 選抜件数: 厳選重視の少数【暫定: 10 件以下】(BS L9)
- 各項目の必須要素:
  - タイトル・媒体名・公開日時
  - 一次ソースへの URL リンク（必須。原文を持たない代わりの出典担保）(BS L80)
  - 選定理由（ヒットした関心軸）(BS L47)
  - 自前生成の要約（LLM 生成。保存可）(BS L75)
- 配信フォーマットの細部は未確定 (BS L115)

## 9. 配信仕様 (BS L78-79)

- アクセスは作成者本人のみ。Cloudflare Access 等の認証で保護する
- 公開 Pages 化・SNS 自動投稿は実装しない（公衆送信への非接触を設計で担保）

## 10. データ保存仕様（法務方針の固定）(BS L72-84)

- 保存 OK: URL / タイトル / 媒体名 / 日時 / フィード提供の要約 / 自前生成の要約 / ベクトル
- 保存 NG: 本文全文の原文永続化
- 実装上の帰結: 本文はパイプライン処理中のみメモリに存在し、Embedding・要約生成後に破棄する
